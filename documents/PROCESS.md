【活動一】

1. 開工前我把任務拆成確認安裝環境與局部根據步驟來執行練習，實際做順序沒改變，因為了解了文檔內容後，覺得練習一搭建 md 設置很重要。
若環境沒搭建完整，都會不小心讓 AI 代替自己并自動完成所有步驟，這樣會提高出錯率。

2. 覺得AI 能快速消化整體的項目邏輯，找出錯誤邏輯和給出優化項目的意見。
例如在練習2時，我會先自行在頁面驗證 bug 是否真實存在後，并寫出該段 Prompt：
“已測試發現頁面在成功創建一個新訂單後，再點擊返回主頁來瀏覽訂單列表，發現新的訂單并不會出現在第一頁中，而是出現在中間的分頁中，麻煩幫修復這問題”
AI會自行檢測并給出修復代碼的提議，自己則只需要一一檢查需要調整的部分，并授權讓AI修改文檔。這部分可以有效的提升以往的工作效率。

3. AI 誤導自己的時候，自己會自行分析邏輯，并反向提出疑問和預測使用該邏輯時，是否會出現怎樣的結果，并讓AI分析。也會讓AI跑 test run 來驗證是否該邏輯部分可以被優化為更適合的處理方式。

4. 透過這些練習，自己會把執行 plan mode 的習慣帶回平日的工作處理方式。若發現AI給的 plan mode 有出錯，也能即時反饋并修正邏輯，直到生成一個滿意的 plan mode，才正式把邏輯搬入工作項目內。

【活動二】
練習3：在 before 會需要執行 SQL 語法來執行查詢資料庫，并從中獲得庫存量資訊。而在開啟 mcp server 并再執行詢問 “哪些商品庫是低於5?” 時，會立即出現一個列表清楚顯示目前有哪些 SKU及商品名稱的庫存量是低於5的。

練習4：有測試了驗證方式，都有呈現應該顯示的結果。

練習5：新增了 orderhub://discount-rules 這個 Resource 和 low_stock_report 這個 Prompt。
折扣規則用 Resource 給、和讓 agent 自己去讀 OrderService.cs 的差別在於：Resource 是團隊共用且受版控的單一事實來源，規則改版（例如折扣％數調整）只要改 OrderService 一處，Resource 動態組出內容就會自動反映，agent 不用重新理解程式碼；讓 agent 自己讀原始碼則每次都要重新解析邏輯，也容易讀到不該暴露的實作細節。
prompt 範本放在 server、和每個人自己打一段話的差別在於：範本進了版控，团队用詞和查詢步驟一致，範本改進（例如多問一個欄位）大家立即受惠；各自打字則每人問法不同、容易漏步驟，且改進經驗無法沉澱給其他人。
